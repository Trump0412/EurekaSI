# 三个 AAAI 项目的方法与代码一致性审查

依据为 catalog 锁定的三个公开仓库及 README。本次未拿到三篇论文全文、服务器脚本、训练日志或最终 checkpoint，因此不能断言论文公式、理论证明、实验数值与代码全部一致，也不能仅凭某条公开入口没有优化器就否定你在服务器上已成功运行的实验。

## 方法是否合理

| 项目 | 从代码能支持的研究假设 | 最需要补足的证据 |
|---|---|---|
| GeoWire / Georoute | 三维对应图约束跨帧信息传播，可能帮助多视图关联与空间关系保持 | 正确图与随机/错配图、图密度和计算量匹配、零门控、单帧/跨帧任务分层；不能只用总分证明对应更准 |
| GeoBridge / SpatialFit | 分层几何 bank + 按需桥接可减少无关几何，并促进语义与空间对齐 | 单层/多层、固定/路由、continuity 分支开关、额外参数匹配；确认所有声称训练的模块确实有梯度且保存/重载 |
| GeoPSRO / gap-4D | 几何状态条件 + 空间相关后训练可能改善动态问题 | RGB-only/geometry-only/RGB+geometry 分开；answer-only/format/完整奖励；真实 rollout 与优化日志；时间词奖励不能直接证明几何推理正确 |

这三个方向有合理动机，但不能由代码结构单独证明新颖性或性能。它们应各有一个主要机制、一个针对性失败模式和一套独立关键消融，避免把同一个几何模块仅换接入层或训练阶段拆成三个无法区分的主张。

## 三个论文的责任边界

- GeoWire 主攻**跨帧对应与信息传播**。核心变量是边/传输，不同时改变训练数据质量和 reward 后再将全部增益归给图。
- GeoBridge 主攻**几何证据的表示与选择**。核心变量是 bank 与查询/桥接，不只对比一个弱融合 baseline。
- GeoPSRO 主攻**动态空间能力的后训练获取**。核心变量是 reward/策略优化与动态证据，不把 preparation 脚本当训练证据。
- CVPR 新研究主攻**数据—监督—表征—迁移的解释链条**。它使用三种结构作为实验工具，而不是第四种堆模块方法。

## 已修与待核实

[完整 AUDIT](AUDIT.md) 记录了可复现的 GeoWire 生成递归，以及 GeoPSRO 最终答案解析、空答案误计正确、数值零丢失。补丁已应用于交付快照，并可由 `source` 自动应用到锁定 checkout；尚未 push 到 GitHub。

公开 GeoPSRO Stage3 主要产出 verl plan；Stage2 主入口是 text+geometry prefix，未像普通 RGB VLM 那样读取像素。这是**公开实现与可能论文主张之间需要对账的点**。请用实际服务器训练脚本、日志、git diff 和模型加载记录核对。代码库已另提供真正的公共 RL 与 RGB 输入路径，但不能把新路径的结果直接替换旧论文实验而不重跑。

原 GeoPSRO 多卡代码中的 rank shuffle、conditional gradient collective、rank-local nonfinite continue 是静态风险，未做原脚本 NCCL 复现。公共训练器的新同步逻辑规避这些设计，但原归档没有被大改。原代码需要独立、可回滚的修复分支与实际多卡验证后再合并。

## 投稿前的最小验收

1. 每张表锁定数据 manifest、scene split、模型/模块权重、实际入口与 config，能重建同一推理输入。
2. 从最终 checkpoint 重新启动全新进程评测；检查 LoRA、geometry、fusion 均被完整加载。
3. paper equation → 实际 loss/reward 函数 → optimizer 参数 → 梯度 → 保存键 → 评测输出形成逐项对应表。
4. 主 benchmark 用官方 scorer；每组报告覆盖率、任务分项与至少关键 seeds。原始解析器修复可能改变历史分数，应重新评分并保留 before/after。
5. 消融必须真的改变模型输入/模块，而不是只更改输出 JSON 中的 geometry_mode 标签。
6. 记录核心增益是否超过训练种子、帧采样和解析差异的波动，再决定主张力度。

在现有证据下，我的判断是：**三个想法均可继续推进，代码与实验叙述的一致性比继续叠加模块更紧迫。** CVPR 路线有潜力，但需要独立问题和跨能力/跨场景/跨应用证据；不能把“三篇方法的代码统一”本身作为其研究贡献。
