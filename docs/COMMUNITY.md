# 社区建设与贡献路线

社区定位：可检查、可复现的空间智能研究基础设施，连接数据、训练、几何、评测与迁移。先积累有证据的配方，不维护无法复现的总分榜。

## 已准备的社区资产

中文主 README、英文入口、资源目录、贡献指南、实验问题模板、CPU CI、三项目规划目录、模型与数据版本目录、补丁、研究协议和验证记录。上传到 GitHub 后即可在同一仓库协作；当前未创建远端仓库或公开发布站点，也没有真实社区成员和贡献记录。

## 建议的协作主题

- Dataset recipes：针对明确 revision/subset 的转换与媒体下载；贡献一条能复现的小样本流程和边界测试。
- Model adapters：优先完成 GeoThinker/GeoSR/SpatialStack 的标准后端，保留官方模型结构；先完成加载与生成，再接训练。
- Geometry：几何尺度、视图顺序、缓存可靠性、几何与 RGB 对齐；不把不同 encoder 的 confidence 当成同一校准量。
- Evaluation：正式指标和受控诊断分开；贡献完整覆盖率及解析统计。
- Training：GPU/NCCL 验收、吞吐与显存、动态 batch、FSDP/ZeRO、checkpoint 精确恢复。
- Transfer：共享动作 head 和标准训练划分的 LIBERO 对照，开放失败记录与时延。

## 结果卡应包含

模型/teacher/geometry 权重 SHA；源码 commit；数据构建脚本与 manifest 哈希；训练初始化和全局 batch；实际 token/样本/图像预算；帧选择、分辨率、prompt、generation、scorer；至少关键 seeds；环境与硬件；逐任务分母、解析率、错误率、统计区间。正式结果不接受 mock 输出，不能只上传截图或最佳总分。

## 开源发布顺序

新公共代码默认 MIT；先核对原归档的再分发权限、论文引用与名称，再上传代码和文档；开启 Issues/Discussions，按数据/模型/评测/训练/应用打标签。CI 通过是公共接口的最低门槛，真实 GPU 回归必须另有明确记录。模型与数据只发布可再分发资产，保留来源与许可证。

这里没有替你设定 GitHub 仓库地址、组织名称、论文作者名单。发布时补全真实信息，不使用占位链接冒充已成立的社区。
