# 研究主线：空间能力从何而来，能否迁移到行动与预测

## 1. 把“空间智能”拆成可验证能力

一个总分无法区分识别物体、恢复几何、跨帧关联和语言猜测。可以将研究目标定义为：**模型是否能从视觉证据形成可跨视角、跨时间保持一致的空间状态，并利用这些状态回答问题、预测变化或选择动作。**

这是拟采用的操作性定义，需要实验支持，不是对空间智能唯一或公认的定义。

| 能力 | 需要的证据 | 避免的混淆 |
|---|---|---|
| 几何量与关系 | 距离、大小、方向、相对位置的任务结果 | 依靠物体类别先验猜位置 |
| 参照系转换 | 视角切换、相机运动、相对/绝对坐标任务 | 将图像左右误当世界左右 |
| 跨帧持续性 | 遮挡后身份、实体对应、状态连续性 | 只看一帧或最后一帧 |
| 动态关系建模 | 时间顺序、关系变化、运动与出现顺序 | 只学习时间词或答案格式 |
| 组合推理 | 多实体、多跳关系、新组合 | 记忆常见句式与选项分布 |
| 可迁移使用 | 导航/操作成功率、未来状态预测 | 只在同分布问答涨分 |

## 2. 第一阶段：建立可信的 baseline

先选一个小 backbone、一套可稳定复现的训练清单、一个主 benchmark 和至少一个异分布 benchmark。这里可以使用 Qwen3-VL-2B 作为工程起点；具体 checkpoint 应由实际可用权重决定，不把模型名称当作性能结论。

固定三套条件：

| 条件 | 用途 |
|---|---|
| 原始模型 + 统一输入协议 | 明确最初空间能力 |
| 相同训练数据的普通 SFT | 衡量数据和 CE 本身的贡献 |
| 相同 SFT checkpoint 的多种后训练 | 比较 RL、OPD、OPSD 的增量 |

先复现实验结果，不直接跑几十组超参。每组保留模型身份、训练样本指纹、累计样本与 token、每任务表现。验证集选择超参，最终测试集只用于冻结方案后的报告。

## 3. 数据、结构、后训练分别改变什么

### 数据因素

比较通用视频 QA、空间单帧/多视图 QA、动态关系 QA，以及它们的混合。采用相同有效样本数或训练 token 预算进行控制；另报告固定 wall-clock/算力的结果。

需要记录：静态/动态比例、帧数、空间问题类型、场景去重、答案长度、reasoning 格式、teacher correctness 过滤率。改变数据混合权重时不要同时换模型结构。

### 结构因素

以普通 VLM 为基线分别接入三个原方法，不一开始叠加所有模块：

| 方法 | 核心待验证假设 | 关键对照 |
|---|---|---|
| GeoWire | 几何约束的跨帧传输提升对应与连续性 | 零门控、随机/错配边、参数量匹配的残差适配器 |
| GeoBridge | 多层几何表示和按需桥接提升空间证据利用 | 单层 bank、固定融合、无局部路由、无连续性分支 |
| GeoPSRO | 几何状态条件和后训练改善动态推理 | 几何前缀无 RGB 的历史版本、RGB 基线、新 RGB+几何版本分别标记 |

“加了 VGGT 后涨分”仍不能证明是几何本身贡献：额外参数、额外训练步骤、数据/分辨率、teacher 表示中的语义信息都可能起作用。需要预算匹配和错配几何对照。

### 后训练因素

| 组别 | 初始化 | 数据 | 主要问题 |
|---|---|---|---|
| SFT | 同一 base | 固定清单 | CE 能否带来稳定增益？ |
| Answer-only RL | 同一 SFT | 固定 QA | 强化答案奖励是否改善泛化？ |
| RL + format | 同一 SFT | 同上 | 格式收益与答案收益能否分开？ |
| 完整 PSRO reward | 同一 SFT | 同上 | 过程关键词是否提供额外有效信号？ |
| OPD | 同一 SFT | 同一问题 | 强教师的分布信息能否转移？ |
| OPSD | 同一 SFT | 同一问题+训练答案 | 自身教师与答案条件是否足够？ |
| Offline KD | 同一 SFT | 教师离线输出 | 在线学生采样是否必要？ |

OPD 对照需再分“同家族强教师”“不同空间训练的同 tokenizer 教师”；不同 tokenizer 教师走 offline KD，不能和 token KL 混成同一种方法。

## 4. 判断模型有没有使用空间证据

以下是后续需要实现/构造的数据干预，不是本版已完成的 benchmark：

- 去掉图像仍能答对多少：检验语言先验与泄漏。
- 只保留一帧/末帧：确定跨帧信息是否必需。
- 在有时间语义的任务上倒序帧：检验答案是否随真实状态变化。
- 使用其他场景的几何缓存：检验几何分支是否只充当正则项。
- 改变无关背景/打乱选项：检验捷径与选项位置偏置。
- 在合法的空间变换下生成成对问题：检验坐标变化后答案的相应变化。

并非所有干预都应使准确率下降。例如世界坐标问题可能应对相机视角变化保持不变；图像左右问题则应随镜像变化。每种干预必须先定义预期答案变化，再测模型，不能把任意掉分都解释为“使用了空间智能”。

建议记录逐题配对一致性、分类别增益、不同场景的分布，而不只记录一个 overall。最终统计使用多个训练随机种子，并按 scene/video 做成组重采样；同一视频的问题不是独立样本。

## 5. 具身应用：先做受控转移实验

研究问题：在相同具身训练数据和 action head 下，经过空间后训练的 backbone，是否比通用 backbone 更容易学习动作、对视角变化更稳健？

先将空间模块作为观测编码器或辅助状态监督，保持 action head、动作表示、控制频率、训练轨迹数量与评测任务一致。可以分别比较冻结 backbone 和等量微调，防止“更多可训练参数”成为解释。

| 实验 | 输出 | 需要控制 |
|---|---|---|
| 目标关系到动作 | 到达/操作成功率 | 动作 tokenizer、动作头、示教数据 |
| 视角/位置变化 | OOD 成功率与碰撞率 | 任务目标、初始化范围 |
| 数据效率 | 随示教数量的学习曲线 | 更新预算、训练步数 |
| 空间问答与控制联合 | 控制收益及空间能力保持 | 联合采样比例、loss scale |

VLM 问答分数不能替代闭环控制评测。本版没有集成机器人环境、动作 tokenizer 或控制 loop，不能直接用 `infer` 的文本输出当安全可执行动作。

## 6. 世界模型应用：评估状态一致性与可用性

先采用较小范围的研究目标：预测未来空间状态、对象关系或几何特征，而不是一开始追求完整 RGB 视频生成。

比较相同预测头接入不同 backbone 后的：未来关系预测、跨帧实体身份、几何一致性、长时误差积累，以及用于规划后的任务成功率。保持未来监督、时间跨度和输出表示一致。

如果采用 Gaussian/3D 状态作为中间表示，需要明确它编码了什么、如何随时间更新、是否可用于动作条件预测。视觉重建变好不直接意味着规划更好；空间问答变好也不直接意味着拥有可用的动态世界模型。

本版将其保留为后续接口方向，尚未实现 action-conditioned rollout、Gaussian renderer 或世界模型训练头。

## 7. 建议的实验执行顺序

1. 核对服务器实际入口与本次三个 commit 的差异，尤其是 GeoPSRO RL 和 RGB 路径。
2. 在真实权重上验收 baseline 推理、SFT checkpoint 重载和 GeoWire 图契约。
3. 固定数据与主/辅评测，完成 SFT、answer-only RL、OPD、OPSD 小预算实验。
4. 对出现稳定增益的方法做数据量、reward、teacher 与几何控制实验。
5. 选出能解释的空间能力变化，再做具身或世界模型的受控迁移。

这条顺序让代码库服务于一个可检验的问题：性能提升来自哪些数据、哪些结构和哪些训练信号，以及这种能力能否在问答之外被使用。
