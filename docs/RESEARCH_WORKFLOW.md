# EurekaSI 研究与应用工作流

EurekaSI 的公共仓库是 https://github.com/Trump0412/EurekaSI。多篇论文和下游应用使用同一套公共实现；每项工作的假设、配置、数据协议与结果证据分别维护。

## 项目边界

- `spatial_intelligence/`：可复用的数据、模型适配、训练、推理、评分与溯源实现。修复公共问题时在此修改，避免在不同论文目录复制训练器。
- `projects/<study>/`：论文或应用的目标、方法差异、实验矩阵、配置说明与验收状态。新项目先添加 README 和所需配置，不预先声明实验结果。
- `configs/`：可复用配置；项目独有配置可随项目维护。机器路径、密钥与本地设置保留在忽略的文件中。
- 外部数据目录和忽略的运行目录：数据、权重、缓存及实验输出。公开仓库只保留可审查的配方、资源版本和允许公开的汇总证据。

## 每项工作的最小记录

1. 明确研究问题或应用任务、基线和成功标准，区分原方法复现、改进方法与诊断实验。
2. 固定代码 commit、数据 revision、媒体/样本身份、场景划分和去重规则；训练与 heldout 分离。明确视觉标记、帧顺序、坐标系、输入预算与评分协议。
3. 保存完整配置、随机种子、模型/adapter 身份和运行环境。比较方法时对齐数据、算力预算与评测条件，记录无法对齐的差异。
4. 保留失败、缺失样本和覆盖率，报告分母与重复运行差异；旧日志只支持产生它的那一版代码。
5. 应用实验另行定义输入输出、资源限制、闭环任务和任务成功指标。QA 分数不能替代机器人成功率或部署验收。

## 变更与验收

每项研究使用独立分支和清晰的提交；通用修复尽早回到公共实现，实验配置绑定实际使用的 commit。新增接口、数据语义或评分变化需要明确说明，并为实质故障增加针对性回归。

静态审查运行 `python scripts/static_check.py` 和 `python scripts/release_check.py`。安装、下载、优化器测试及实验仅在任务要求运行时执行；当前静态通过不代表运行验收完成。CI 的打包和 CPU 运行任务仅在手动触发 workflow 时执行，避免首次发布源码自动启动运行实验。

未来运行验收从小规模真实输入和完整测试开始，再扩大模型、数据与应用范围。报告当前证据到 [VALIDATION](VALIDATION.md)，待完善部分见 [READINESS_REVIEW](READINESS_REVIEW.md)。正式版本发布应对应明确 commit 和验收范围。
